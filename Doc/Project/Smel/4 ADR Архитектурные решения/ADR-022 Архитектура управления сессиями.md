# 1. Назначение

Настоящее архитектурное решение определяет принципы управления пользовательскими сессиями в проекте **Smart Electric (SmEl)**.

Решение устанавливает правила создания, идентификации, использования и завершения сессий для гостей и аутентифицированных пользователей.

# 2. Область применения

Решение применяется к:

- гостевым пользователям;
    
- аутентифицированным пользователям;
    
- REST API;
    
- Frontend Vue 3;
    
- гостевой корзине;
    
- операциям, требующим идентификации текущей сессии.
    

Конкретный механизм реализации сессий настоящим решением не фиксируется.

# 3. Основная часть

## 3.1. Понятие сессии

Сессия представляет собой временный контекст взаимодействия клиента с Backend.

Сессия позволяет Backend связать последовательность запросов одного клиента с единым контекстом взаимодействия.

Сессия не является заменой учётной записи пользователя и не определяет его коммерческие условия.

## 3.2. Гостевая сессия

Гостевой пользователь не проходит аутентификацию, однако Backend должен иметь возможность однозначно связать его запросы в рамках текущей сессии.

Гостевая сессия используется, в частности, для работы гостевой корзины.

Гостевая корзина существует только в рамках текущей сессии и не должна сохраняться как постоянная корзина пользователя после завершения сессии.

## 3.3. Сессия аутентифицированного пользователя

После успешной аутентификации сессия связывается с соответствующим User.

Идентификация User и проверка его полномочий выполняются в соответствии с ADR-021.

Сессия не изменяет модель User или Customer и не заменяет отношения между этими сущностями.

Корзина аутентифицированного клиента сохраняется независимо от завершения конкретной пользовательской сессии в соответствии с ADR-013.

## 3.4. Сессия и корзина

Сессия и корзина являются различными архитектурными сущностями.

Для гостя:

```
Guest
  │
  ▼
Session
  │
  ▼
Guest Cart
  │
  ▼
Cart Items
```

Для аутентифицированного пользователя:

```
User
  │
  ▼
Session
  │
  └──────────────┐
                 ▼
             Customer
                 │
                 ▼
                Cart
                 │
                 ▼
             Cart Items
```

Завершение сессии не должно автоматически удалять корзину аутентифицированного пользователя.

## 3.5. Жизненный цикл сессии

Сессия проходит следующие логические состояния:

1. создание;
    
2. активное использование;
    
3. истечение срока действия или завершение;
    
4. прекращение действия.
    

Продолжительность сессии определяется отдельными параметрами безопасности и реализации.

Конкретный срок действия сессии настоящим ADR не фиксируется.

## 3.6. Безопасность сессии

Сессионный идентификатор или иной механизм идентификации сессии должен:

- быть уникальным;
    
- быть непредсказуемым;
    
- передаваться защищённым способом;
    
- не содержать чувствительных данных;
    
- иметь контролируемый срок действия;
    
- становиться недействительным после завершения сессии.
    

Механизм хранения и передачи идентификатора определяется последующими решениями по безопасности.

# 4. Правила

1. Сессия является временным контекстом взаимодействия клиента с Backend.
    
2. Сессия не заменяет User или Customer.
    
3. Гостевой пользователь может иметь сессию без аутентификации.
    
4. Гостевая корзина существует только в рамках текущей сессии.
    
5. Корзина аутентифицированного клиента не привязана исключительно к продолжительности одной сессии.
    
6. После аутентификации Backend должен однозначно определить соответствующего User.
    
7. Завершение сессии не должно удалять постоянные данные аутентифицированного пользователя.
    
8. Сессионный идентификатор не должен содержать чувствительные данные.
    
9. Сессионный идентификатор должен быть защищён от подмены и повторного использования после завершения сессии.
    
10. Frontend не должен самостоятельно определять действительность сессии.
    
11. Backend является источником истины для состояния сессии.
    
12. Срок действия сессии определяется политиками безопасности и конкретным механизмом реализации.
    
13. Жизненный цикл Cart Item определяется отдельным архитектурным решением ADR-024.
    
14. Конкретный механизм реализации сессий определяется отдельным техническим решением.

# 6. Заключительные положения

В SmEl сессия рассматривается как временный контекст взаимодействия клиента с Backend.

Архитектура предусматривает различное использование сессий для гостей и аутентифицированных пользователей.

Гостевая сессия обеспечивает работу временных данных, включая гостевую корзину. Для аутентифицированного пользователя завершение сессии не приводит к потере постоянных данных, включая сохранённую корзину.

Конкретный механизм реализации, сроки действия и параметры безопасности сессий определяются последующими архитектурными и техническими решениями.
