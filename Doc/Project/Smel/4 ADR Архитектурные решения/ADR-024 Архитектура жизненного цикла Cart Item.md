# 1. Назначение

Настоящее архитектурное решение определяет жизненный цикл элемента корзины `Cart Item` в проекте **Smart Electric (SmEl)**.

Решение устанавливает правила создания, изменения, проверки актуальности, сохранения и удаления `Cart Item` в зависимости от состояния корзины и типа пользователя.

# 2. Область применения

Решение применяется к:

- гостевым корзинам;
    
- корзинам аутентифицированных пользователей;
    
- элементам корзины `Cart Item`;
    
- операциям добавления и изменения количества товара;
    
- проверке актуальности корзины;
    
- процессу Checkout;
    
- созданию Order.
    

Настоящее решение не определяет правила оплаты, доставки и резервирования товара.

# 3. Основная часть

## 3.1. Cart Item

`Cart Item` представляет собой элемент корзины, связывающий конкретный товар с корзиной и содержащий выбранное пользователем количество.

Логическая связь:

```
Product / SKU
      │
      ▼
  Cart Item
      │
      ▼
    Cart
```

`Cart Item` является временным коммерческим представлением выбранного товара.

Он не является частью заказа и не заменяет `Order Item`.

## 3.2. Создание Cart Item

`Cart Item` создаётся при добавлении товара в корзину.

При создании должны быть проверены:

- существование товара;
    
- доступность товара для добавления в корзину;
    
- допустимость указанного количества;
    
- возможность выполнения операции текущим субъектом.
    

Повторное добавление того же товара в ту же корзину должно приводить к изменению количества существующего `Cart Item`, если иное не определено бизнес-правилами.

## 3.3. Изменение Cart Item

Пользователь может изменять количество товара в корзине при наличии соответствующих прав.

При изменении количества Backend должен повторно проверить применимые ограничения.

Frontend не является источником истины относительно допустимого количества.

## 3.4. Актуальность Cart Item

Наличие `Cart Item` в корзине не гарантирует сохранение исходных условий продажи.

Перед переходом к Checkout должна выполняться проверка актуальности.

Проверка может включать:

- существование товара;
    
- доступность товара для продажи;
    
- актуальность цены;
    
- актуальность скидок;
    
- актуальность акций;
    
- доступность необходимого количества;
    
- актуальность коммерческих условий;
    
- допустимость выбранной валюты и других применимых параметров.
    

Результатом проверки является актуальный набор данных, на основании которого может быть сформирован Checkout.

## 3.5. Изменение коммерческих условий

Стоимость, скидки и акции являются частью коммерческого блока ценообразования в соответствии с ADR-010.

Изменение цены, скидки или акции после добавления товара в корзину не должно считаться ошибкой само по себе.

При проверке актуальности Backend определяет действующие коммерческие условия.

Пользователь должен получить актуальную информацию до создания заказа.

## 3.6. Недоступный товар

Если товар больше не доступен для продажи, `Cart Item` не должен использоваться для создания заказа.

Backend должен сообщить о невозможности продолжения Checkout и предоставить актуальное состояние корзины.

Автоматическое физическое удаление элемента корзины при каждой такой ситуации не является обязательным.

Конкретная стратегия удаления или сохранения недоступных элементов может быть уточнена правилами реализации.

## 3.7. Срок существования Cart Item

Для `Cart Item` не устанавливается универсальный фиксированный числовой срок существования.

Срок фактического существования зависит от:

- типа корзины;
    
- состояния корзины;
    
- активности пользователя;
    
- политики хранения данных;
    
- актуальности самого товара;
    
- последующих бизнес-правил.
    

Для гостя `Cart Item` существует только в рамках текущей гостевой сессии.

Для аутентифицированного пользователя `Cart Item` может сохраняться вместе с постоянной корзиной между пользовательскими сессиями.

## 3.8. Завершение жизненного цикла

Жизненный цикл `Cart Item` завершается при:

- удалении товара пользователем;
    
- удалении всей корзины;
    
- завершении срока хранения согласно установленной политике;
    
- иных предусмотренных бизнес-операциях.
    

Создание `Order` не должно рассматриваться как простое преобразование существующего `Cart Item`.

При создании заказа формируется самостоятельный `Order Item`, содержащий зафиксированные коммерческие условия заказа.

# 4. Правила

1. `Cart Item` является частью корзины и не является частью заказа.
    
2. Каждый `Cart Item` относится к конкретной корзине.
    
3. `Cart Item` содержит выбранное количество конкретного товара.
    
4. Создание и изменение `Cart Item` выполняются через Backend.
    
5. Frontend не является источником истины для допустимого количества и коммерческих условий.
    
6. При добавлении товара Backend проверяет применимые ограничения.
    
7. Перед Checkout обязательна проверка актуальности `Cart Item`.
    
8. Цена, скидки и акции должны проверяться на актуальность перед созданием заказа.
    
9. Наличие товара в корзине не означает гарантированного наличия товара на складе.
    
10. Наличие `Cart Item` не резервирует товар, если отдельным решением не предусмотрено иное.
    
11. Гостевой `Cart Item` существует только в рамках текущей гостевой сессии.
    
12. `Cart Item` аутентифицированного пользователя может сохраняться между сессиями.
    
13. Создание заказа приводит к формированию самостоятельного `Order Item`.
    
14. Изменение данных товара после добавления в корзину не должно автоматически изменять уже сохранённый `Cart Item` без процедуры актуализации.
    
15. Фиксированный числовой срок хранения `Cart Item` настоящим ADR не определяется.
    
16. Удаление `Cart Item` должно выполняться контролируемой бизнес-операцией.
    
17. Актуальность корзины проверяется Backend перед Checkout.
    
18. Правила резервирования товара определяются отдельным архитектурным решением.

# 6. Заключительные положения

`Cart Item` рассматривается как временный элемент корзины, жизненный цикл которого зависит от типа корзины, состояния товара и актуальности коммерческих условий.

Для гостя элемент существует только в рамках текущей сессии. Для аутентифицированного пользователя элемент может сохраняться вместе с корзиной между сессиями.

Перед Checkout выполняется обязательная проверка актуальности товара, количества и коммерческих условий.

При создании заказа формируется самостоятельный `Order Item`, что обеспечивает независимость заказа от последующих изменений каталога, цен и остатков.

Фиксированный числовой срок хранения `Cart Item` настоящим решением не определяется и может быть установлен отдельной политикой.
