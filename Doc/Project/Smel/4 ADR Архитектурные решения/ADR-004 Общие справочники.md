# 1. Назначение

Документ фиксирует архитектурное решение по организации общих справочных данных проекта **Smart Electric (SmEl)**.

Решение определяет единое место хранения общих справочников и правила их использования функциональными модулями системы.

# 2. Область применения

Решение распространяется на Backend и базу данных проекта SmEl.

Общие справочники размещаются в отдельном Django-приложении:

```
backend/
└── apps/
    └── lists/
```

Приложение `lists` является единым источником справочных данных для функциональных модулей системы.

# 3. Основная часть

В приложении `lists` размещаются справочники, которые используются двумя и более функциональными модулями проекта.

Примеры общих справочников:


Конкретный состав справочников может расширяться по мере развития проекта.

## 3.1. Единый источник справочных данных

Каждый общий справочник должен иметь единственную реализацию в системе.

Функциональные приложения используют соответствующие модели из `lists`, не создавая собственных дублирующих реализаций.

## 3.2. Использование справочников

Функциональные приложения, включая `catalog`, `cart`, `orders`, `prices`, `seo` и другие, могут ссылаться на справочники из `lists`.

Связь с элементами справочников реализуется средствами Django и реляционной модели данных, включая:

- `ForeignKey`;
    
- `ManyToManyField`.
    

## 3.3. Локализация

Структура справочников должна обеспечивать возможность локализации значений.

Для реализации локализации допускается использование `django-modeltranslation` или соответствующего механизма, принятого в технологической архитектуре проекта.

# 4. Правила

В рамках данного архитектурного решения устанавливаются следующие правила:

1. Каждый общий справочник хранится только в одном месте.
    
2. Запрещается создавать дублирующие реализации общих справочников в других приложениях.
    
3. Функциональные приложения используют единые модели справочников из `lists`.
    
4. Каждое значение справочника должно иметь уникальный идентификатор.
    
5. Структура справочников должна обеспечивать возможность локализации.
    
6. Изменения структуры справочников выполняются через миграции Django.
    
7. Функциональные приложения могут использовать справочники из `lists`, но не должны самостоятельно создавать их дублирующие структуры.
    
8. Новый справочник должен добавляться в `lists`, если он предназначен для использования двумя и более функциональными модулями.
    
9. Сущность, используемая исключительно внутри одного приложения и не предназначенная для повторного использования, не должна помещаться в `lists` только ради централизации.
    
10. Изменения общих справочников требуют оценки влияния на зависимые приложения, данные и API.
    

# 5. Причины выбора

Централизация общих справочников в приложении `lists` обеспечивает:

- единый источник справочных данных;
    
- повторное использование моделей во всех функциональных модулях;
    
- снижение дублирования данных и кода;
    
- согласованность классификации;
    
- упрощение сопровождения и миграций;
    
- возможность централизованного администрирования через Django Admin.
    

# 6. Последствия

## 6.1. Преимущества

Решение обеспечивает:

- единую классификацию данных во всём проекте;
    
- отсутствие дублирования справочников;
    
- повторное использование справочных моделей;
    
- упрощение расширения набора справочников;
    
- повышение целостности данных;
    
- единый подход к администрированию справочных данных.
    

## 6.2. Ограничения

Решение требует:

- соблюдения границы приложения `lists`;
    
- анализа потенциальной области использования нового справочника;
    
- оценки влияния изменений общих справочников на зависимые приложения;
    
- предотвращения размещения в `lists` сущностей, являющихся локальными для одного функционального приложения.

# 8. Заключительные положения

Приложение `lists` является единым архитектурным местом размещения общих справочников SmEl.

Централизация справочных данных обеспечивает единообразие классификации, исключает дублирование и упрощает использование справочных сущностей различными функциональными модулями.

Граница между общим справочником и локальной сущностью определяется областью его использования: справочник, используемый двумя и более функциональными модулями, относится к `lists`; сущность, имеющая локальную область применения, остаётся в соответствующем приложении.
