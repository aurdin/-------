# 1. Назначение

Документ фиксирует архитектурное решение по использованию SQL-представлений (**VIEW**) в проекте **Smart Electric (SmEl)**.

Решение определяет назначение представлений, место их размещения и основные правила их использования.

# 2. Область применения

Решение распространяется на Backend и базу данных проекта SmEl.

SQL-представления используются для оптимизации чтения данных, формирования сложных выборок и подготовки данных для API и Frontend.

Все представления и связанные с ними модели Django размещаются в отдельном приложении:

```
backend/
└── apps/
    └── dbview/
```

Приложение `dbview` предназначено исключительно для работы с данными в режиме **только чтение (read-only)**.

# 3. Основная часть

SQL-представления используются как специализированный слой подготовки данных между основными таблицами базы данных и компонентами Backend.

Представления позволяют объединять и подготавливать данные для последующего использования Django, Django REST Framework и Frontend.

## 3.1. Назначение представлений

SQL-представления используются для:

- объединения данных из нескольких таблиц;
    
- подготовки данных для каталога товаров;
    
- формирования результатов поиска;
    
- реализации фильтрации;
    
- подготовки данных для сравнения товаров;
    
- формирования прайс-листов;
    
- подготовки аналитических и отчётных данных.
    

## 3.2. Организация представлений

Каждое представление должно решать одну конкретную задачу.

Для каждого представления создаётся соответствующая Django-модель, предназначенная для работы с результатами представления:

```
managed = False
```

Модели представлений могут использоваться в Django Admin, Django REST Framework и сервисах Backend только для чтения.

## 3.3. Логическая схема

```
Таблицы PostgreSQL
        │
        ├── Product
        ├── Price
        ├── Brand
        ├── Series
        ├── Category
        └── ...
               │
               ▼
        SQL VIEW (dbview)
               │
               ▼
   Django Model (managed = False)
               │
               ▼
   Django REST Framework
               │
               ▼
          Frontend (Vue)
```

# 4. Правила

В рамках данного архитектурного решения устанавливаются следующие правила:

1. SQL-представления размещаются в приложении `dbview`.
    
2. Каждое представление должно решать одну конкретную задачу.
    
3. Представления не должны содержать бизнес-логику приложения.
    
4. Представления используются преимущественно для операций чтения.
    
5. Изменение данных выполняется через основные таблицы, а не через `VIEW`.
    
6. Каждому представлению должна соответствовать отдельная Django-модель с параметром `managed = False`.
    
7. Модели представлений могут использоваться в Django Admin, Django REST Framework и сервисах Backend только для чтения.
    
8. При изменении структуры основных таблиц необходимо актуализировать связанные SQL-представления и модели Django.
    
9. Сложные представления должны сопровождаться соответствующей документацией.
    
10. Представления не должны использоваться для дублирования бизнес-сущностей, являющихся источниками данных.
    

# 5. Причины выбора

Использование SQL-представлений выбрано по следующим причинам:

- повышение производительности при выполнении сложных запросов;
    
- уменьшение количества сложной логики в Django ORM;
    
- повторное использование подготовленных выборок;
    
- формирование единого источника подготовленных данных для API;
    
- упрощение разработки Frontend за счёт получения уже подготовленных данных.
    

# 6. Последствия

## 6.1. Преимущества

Решение обеспечивает:

- повышение эффективности запросов к каталогу и поиску;
    
- уменьшение объёма сложного SQL-кода в прикладной части Backend;
    
- единообразие данных, возвращаемых API;
    
- упрощение сопровождения сложных выборок;
    
- возможность централизованной оптимизации запросов;
    
- повторное использование подготовленных представлений различными компонентами Backend.
    

## 6.2. Ограничения

Решение требует:

- использования представлений как слоя чтения;
    
- исключения изменения данных через `VIEW`;
    
- документирования сложных представлений;
    
- актуализации представлений и соответствующих Django-моделей при изменении структуры исходных таблиц;
    
- контроля соответствия представлений архитектуре основных данных.

# 8. Заключительные положения

SQL-представления являются специализированным слоем подготовки данных для операций чтения в архитектуре SmEl.

Приложение `dbview` является единым местом размещения SQL-представлений и связанных с ними Django-моделей.

Данное решение завершает базовый архитектурный фундамент SmEl в части общих принципов организации Backend и данных.

Следующие архитектурные решения могут определять отдельные подсистемы и функциональные области проекта, опираясь на решения ADR-001–ADR-006.
