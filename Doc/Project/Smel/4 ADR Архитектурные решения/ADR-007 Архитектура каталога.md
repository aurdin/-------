# 1. Назначение

Документ фиксирует архитектурное решение по организации каталога проекта **Smart Electric (SmEl)**.

Решение определяет логическую структуру иерархии каталога, назначение её уровней и основные принципы классификации товаров.

# 2. Область применения

Решение распространяется на каталог товаров SmEl и связанные с ним механизмы навигации, фильтрации, URL, REST API и SEO.

Физическая реализация структуры каталога в PostgreSQL, Django и REST API определяется последующими архитектурными решениями.

# 3. Основная часть

Каталог проекта **Smart Electric (SmEl)** строится по многоуровневой иерархической модели, которая отражает маркетинговую структуру каталога и обеспечивает удобную навигацию, фильтрацию и масштабирование.

## 3.1. Иерархия каталога

Базовая иерархия каталога имеет следующий вид:

```
Showcase
    │
    └── Category
            │
            └── Group
                    │
                    └── Type
                            │
                            └── Configuration
                                    │
                                    └── Execution
                                            │
                                            ├── Brand
                                            │       │
                                            │       └── Series
                                            │               │
                                            │               └── SKU
                                            │
                                            └── SKU
```

## 3.2. Назначение уровней

|Уровень|Назначение|
|---|---|
|**Showcase**|Витрина каталога, например: Дом, Коммерция, Промышленность, Зарядные станции, Умный дом и др.|
|**Category**|Основная категория товаров: Электроустановочные изделия, Модульное оборудование, Кабельные системы и т. д.|
|**Group**|Группа однотипных изделий: Розетки, Выключатели, Автоматические выключатели и др.|
|**Type**|Тип изделия, определяющий его функциональное назначение.|
|**Configuration**|Конфигурация изделия: число постов, полюсов, модулей, каналов и т. п.|
|**Execution**|Конструктивное или техническое исполнение изделия.|
|**Brand**|Производитель продукции.|
|**Series**|Серия производителя.|
|**SKU**|Конкретная товарная позиция (артикул).|

## 3.3. Роль Brand и Series

**Brand** и **Series** участвуют в классификации товарной продукции, но не являются структурообразующими уровнями основной иерархии каталога.

Структура каталога должна оставаться независимой от конкретного производителя.

## 3.4. Конечный уровень каталога

**SKU** представляет конкретную товарную позицию и является конечным уровнем товарной иерархии.

Товарные позиции могут быть связаны с соответствующими уровнями классификации в зависимости от принятой структуры каталога.

# 4. Правила

В рамках данного архитектурного решения устанавливаются следующие правила:

1. Каждый уровень иерархии отвечает только за свою область классификации.
    
2. Иерархия является логической основой каталога SmEl.
    
3. Каждый элемент иерархии имеет одного непосредственного родителя.
    
4. Товары (SKU) размещаются только на конечном уровне товарной иерархии.
    
5. `Brand` и `Series` являются частью товарной классификации, но не определяют структуру основной иерархии каталога.
    
6. Структура каталога должна быть независимой от конкретного производителя.
    
7. Добавление новых товарных направлений должно выполняться без изменения существующего принципа иерархии.
    
8. Каждый новый уровень классификации должен иметь чётко определённую бизнес-роль.
    
9. Изменение структуры верхних уровней должно учитывать влияние на навигацию, URL и SEO.
    
10. Физическая реализация иерархии не должна изменять принятую логическую концепцию каталога без отдельного архитектурного решения.
    

# 5. Причины выбора

Многоуровневая иерархическая модель выбрана по следующим причинам:

- соответствие логике построения профессиональных каталогов электротехнической продукции;
    
- удобная навигация пользователей;
    
- упрощение построения URL и хлебных крошек;
    
- возможность применения единого механизма фильтрации на различных уровнях;
    
- поддержка товаров разных производителей в рамках единой классификации;
    
- масштабируемость при добавлении новых товарных направлений.
    

# 6. Последствия

## 6.1. Преимущества

Решение обеспечивает:

- единую архитектуру каталога для различных групп товаров;
    
- отсутствие дублирования категорий и групп;
    
- независимость структуры каталога от производителя;
    
- простую интеграцию новых брендов и серий;
    
- удобное построение дерева каталога;
    
- единый подход к формированию REST API;
    
- возможность формирования навигации, фильтров и SEO на различных уровнях каталога.
    

## 6.2. Ограничения

Решение требует:

- анализа влияния изменений верхних уровней на навигацию, URL и SEO;
    
- чёткого определения бизнес-роли каждого уровня классификации;
    
- размещения товарных позиций только на конечном уровне иерархии;
    
- сохранения независимости основной структуры каталога от производителя.

# 8. Заключительные положения

Многоуровневая иерархическая модель является базовым принципом организации каталога SmEl.

Данное решение фиксирует **логическую структуру каталога**, но не определяет конкретную физическую реализацию в PostgreSQL, Django, REST API и административном интерфейсе.

Последующие архитектурные решения могут определять физическую модель, механизмы навигации, фильтрации, API и другие аспекты реализации каталога без изменения принятой концепции классификации.
