# 1. Назначение

Настоящее архитектурное решение определяет принцип организации изображений, документов и других медиа-ресурсов в проекте **Smart Electric (SmEl)**.

Решение фиксирует медиа-контент как самостоятельную подсистему, отделенную от сущностей каталога и независимую от конкретной технологии физического хранения файлов.

# 2. Область применения

Решение применяется к:

- изображениям товаров;
    
- изображениям серий;
    
- логотипам брендов;
    
- техническим паспортам;
    
- инструкциям по эксплуатации;
    
- сертификатам;
    
- каталогам;
    
- презентациям;
    
- видеоматериалам;
    
- архивам;
    
- другим документам и медиафайлам.
    

Подсистема может использоваться не только каталогом товаров, но и другими функциональными областями SmEl.

# 3. Основная часть

## 3.1. Самостоятельность медиа-контента

В SmEl изображения, документы и другие медиафайлы не хранятся непосредственно в сущностях каталога.

Каждый медиа-ресурс является самостоятельным объектом и связывается с товарами или другими сущностями через отдельную подсистему.

## 3.2. Логическая модель

```
Media
   │
   ├── Image
   ├── Document
   ├── Video
   ├── Archive
   ├── Certificate
   ├── Manual
   └── Other
        │
        ▼
MediaLink
        │
        ├── SKU
        ├── Category
        ├── Series
        ├── Brand
        └── Other Entity
```

## 3.3. Типы медиа

Подсистема поддерживает различные типы файлов, включая:

- изображения товаров;
    
- изображения серий;
    
- логотипы брендов;
    
- технические паспорта;
    
- инструкции по эксплуатации;
    
- сертификаты;
    
- каталоги в формате PDF;
    
- презентации;
    
- видеоматериалы;
    
- архивы;
    
- прочие документы.
    

# 4. Правила

1. Каждый медиафайл хранится только один раз.
    
2. Один файл может быть связан с несколькими сущностями.
    
3. Одна сущность может иметь любое количество связанных файлов.
    
4. Связи между файлами и сущностями реализуются через отдельную связь `MediaLink`.
    
5. Удаление связи не приводит автоматически к удалению самого файла.
    
6. Физическое хранение файлов отделено от бизнес-логики приложения.
    
7. Каждый медиафайл имеет уникальный идентификатор.
    
8. Объект `Media` содержит сведения о самом файле, включая тип, имя, путь или ссылку на хранилище, размер, MIME-тип, контрольную сумму и другие необходимые метаданные.
    
9. Порядок отображения файлов определяется связью `MediaLink`, а не самим файлом.
    
10. Для сущности допускается назначение одного файла основным, например главного изображения товара.
    
11. Производные версии файла, такие как миниатюры и изображения различных размеров, рассматриваются как производные ресурсы исходного файла.
    
12. Операции загрузки, изменения и удаления медиа выполняются через централизованный механизм управления медиа.
    
13. Удаление файла допускается только после проверки отсутствия активных связей.
    
14. Права доступа к медиа определяются политиками безопасности приложения.
    

# 5. Обоснование

Выделение медиа-контента в самостоятельную подсистему выбрано по следующим причинам:

- отсутствие дублирования файлов;
    
- повторное использование одного файла различными объектами;
    
- независимость структуры каталога от способа хранения медиа;
    
- централизованное управление контентом;
    
- возможность изменения физического хранилища без изменения бизнес-логики;
    
- подготовка к использованию облачных и объектных хранилищ;
    
- возможность подключения CDN и механизмов обработки производных ресурсов.
    

# 6. Последствия

## 6.1. Преимущества

- единая система хранения медиа;
    
- поддержка нескольких изображений и документов для одного товара;
    
- возможность связывать один файл с несколькими объектами;
    
- простое масштабирование объема хранилища;
    
- готовность к использованию CDN;
    
- возможность использования S3-совместимых объектных хранилищ;
    
- снижение объема дублируемых данных;
    
- повторное использование подсистемы медиа в различных функциональных областях SmEl.
    

## 6.2. Ограничения

- сущности каталога не должны хранить физические пути к файлам непосредственно;
    
- операции с медиа должны выполняться через централизованный механизм;
    
- удаление файла требует проверки существующих связей;
    
- права доступа должны контролироваться средствами безопасности приложения;
    
- конкретная технология физического хранения файлов данным решением не определяется.

# 8. Заключительные положения

Настоящее решение определяет архитектурный принцип самостоятельного хранения и управления медиа-контентом.

Архитектура не зависит от конкретной технологии физического хранения файлов и допускает:

- использование локального файлового хранилища в процессе разработки;
    
- переход на облачное или объектное хранилище без изменения бизнес-логики;
    
- подключение CDN;
    
- автоматическую генерацию миниатюр, WebP-версий и других производных ресурсов.
    

Подсистема медиа является универсальной и может использоваться как каталогом товаров, так и другими функциональными областями SmEl.
