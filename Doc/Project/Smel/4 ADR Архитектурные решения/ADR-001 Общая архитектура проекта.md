# 1. Назначение

Документ фиксирует общее архитектурное решение проекта **Smart Electric (SmEl)** и определяет базовую структуру приложения, разделение ответственности между основными уровнями системы и принцип их взаимодействия.

# 2. Область применения

Решение распространяется на основную информационную систему SmEl и определяет архитектурное разделение на:

- Frontend;
    
- Backend;
    
- Database.
    

Решение является базовым для последующих архитектурных решений, определяющих устройство отдельных частей системы.

# 3. Основная часть

Проект **Smart Electric (SmEl)** строится на основе трёхуровневой архитектуры (**Three-Tier Architecture**).

Архитектурные уровни:

**Frontend → REST API → Backend → Database**

## 3.1. Frontend

Frontend является пользовательским уровнем системы.

Используемые технологии:

- Vue 3;
    
- TypeScript;
    
- Pinia;
    
- Vue Router;
    
- Tailwind CSS;
    
- Axios.
    

Frontend отвечает за пользовательский интерфейс, навигацию, управление состоянием клиентского приложения и взаимодействие с Backend через REST API.

## 3.2. Backend

Backend является серверным уровнем системы.

Используемые технологии:

- Django;
    
- Django REST Framework;
    
- Django Admin;
    
- ModelTranslation.
    

Backend предоставляет REST API и содержит бизнес-логику приложения.

## 3.3. Database

Database является уровнем хранения данных.

Используемая технология:

- PostgreSQL.
    

Frontend не имеет прямого доступа к Database.

Backend является посредником между прикладными компонентами системы и Database.

## 3.4. Основной принцип взаимодействия

Взаимодействие между Frontend и Backend осуществляется через REST API с использованием формата JSON.

Основной поток взаимодействия:

**Frontend → REST API → Backend → Database**

Результат обработки возвращается клиенту через REST API.

# 4. Правила

В рамках данного архитектурного решения устанавливаются следующие правила:

1. Frontend и Backend являются логически разделёнными архитектурными уровнями.
    
2. Взаимодействие Frontend с Backend осуществляется через REST API.
    
3. Frontend не обращается непосредственно к Database.
    
4. Бизнес-логика реализуется на стороне Backend.
    
5. Backend является центральной точкой доступа к данным и реализации критической бизнес-логики.
    
6. Database используется для централизованного хранения данных системы.
    
7. Конкретная организация компонентов Backend, Database и Frontend определяется отдельными архитектурными решениями.

# 6. Заключительные положения

Принятое решение устанавливает базовое архитектурное разделение SmEl на Frontend, Backend и Database.

Решение обеспечивает разделение ответственности, независимое развитие клиентской и серверной частей, централизованное управление бизнес-логикой и исключение прямого доступа Frontend к Database.

Конкретные технологические и архитектурные решения отдельных компонентов определяются соответствующими документами серии ADR, AMD и STD.
