# 1. Назначение

Документ фиксирует архитектурное решение по организации базы данных проекта **Smart Electric (SmEl)**.

Решение определяет используемую систему управления базой данных, основные категории данных и общие правила организации объектов базы данных.

# 2. Область применения

Решение распространяется на базу данных Backend проекта SmEl.

В рамках решения определяются следующие категории данных:

- справочники (**Lists**);
    
- рабочие данные (**Business Data**);
    
- представления (**Views**);
    
- служебные данные (**System Data**).
    

# 3. Основная часть

В качестве системы управления базой данных проекта **Smart Electric (SmEl)** используется **PostgreSQL**.

База данных организуется с разделением данных по их назначению.

## 3.1. Справочники

Справочники содержат общие классификаторы и другие данные, используемые различными функциональными областями системы.

Примеры:

- Category;
    
- Brand;
    
- Series;
    
- Color;
    
- IP;
    
- другие общие справочные сущности.
    

Общие справочники относятся к отдельной функциональной области `lists`.

## 3.2. Рабочие данные

Рабочие данные представлены основными сущностями системы, участвующими в бизнес-процессах.

Примеры:

- Product;
    
- ProductPrice;
    
- Cart;
    
- CartItem;
    
- Order;
    
- другие бизнес-сущности.
    

## 3.3. Представления

SQL-представления (**Views**) используются для объединения, агрегации и подготовки данных преимущественно для операций чтения.

Примеры:

- CatalogView;
    
- SearchView;
    
- PriceView;
    
- другие представления.
    

Представления не являются самостоятельным источником бизнес-логики.

## 3.4. Служебные данные

Служебные данные включают объекты, необходимые Django и используемым компонентам инфраструктуры.

К ним относятся, например:

- таблицы аутентификации;
    
- таблицы Django;
    
- таблицы сессий;
    
- таблицы миграций;
    
- другие служебные объекты.
    

# 4. Правила

В рамках данного архитектурного решения устанавливаются следующие правила:

1. PostgreSQL используется как основная система управления базой данных SmEl.
    
2. Каждая таблица должна представлять одну определённую предметную сущность или служебное назначение.
    
3. Дублирование одних и тех же данных между независимыми таблицами должно исключаться.
    
4. Связи между сущностями реализуются с использованием внешних ключей (`ForeignKey`) или соответствующих механизмов реляционной модели.
    
5. Связи «многие ко многим» реализуются посредством промежуточных таблиц.
    
6. SQL-представления используются преимущественно для чтения и не должны содержать бизнес-логику.
    
7. Изменения структуры базы данных выполняются посредством миграций Django, если объект может быть корректно представлен средствами миграционного механизма.
    
8. Объекты, требующие специализированного SQL, например сложные `VIEW`, могут создаваться и поддерживаться с использованием ручного SQL.
    
9. Структура базы данных должна оставаться согласованной с моделями Django и архитектурой Backend.
    
10. Изменения общих справочников, связей и других общих компонентов должны учитывать влияние на существующие данные и API.
    

# 5. Причины выбора

PostgreSQL выбран в качестве СУБД SmEl по следующим причинам:

- производительность;
    
- надёжность и стабильность;
    
- поддержка сложных SQL-запросов;
    
- поддержка представлений и индексов;
    
- интеграция с Django ORM;
    
- возможности оптимизации и масштабирования по мере роста проекта.
    

# 6. Последствия

## 6.1. Преимущества

Решение обеспечивает:

- единую и согласованную структуру данных;
    
- централизованное хранение данных;
    
- эффективную работу с каталогом товаров;
    
- возможность построения сложных запросов, фильтрации и поиска;
    
- использование возможностей PostgreSQL для оптимизации хранения и чтения данных.
    

## 6.2. Ограничения

Решение требует:

- соблюдения согласованной структуры данных;
    
- контроля изменений общих сущностей и связей;
    
- документирования сложных SQL-представлений;
    
- синхронного сопровождения представлений и соответствующих моделей или компонентов Django;
    
- анализа влияния изменений структуры базы на API и зависимые компоненты.

# 8. Заключительные положения

PostgreSQL является основной системой управления базой данных проекта SmEl.

Организация базы данных основывается на разделении справочных, рабочих, представленных и служебных данных.

Структура базы должна обеспечивать целостность данных и соответствовать архитектурным границам Backend.

Конкретная структура физических таблиц, индексов и SQL-реализаций определяется соответствующими моделями, реализацией и специализированными архитектурными решениями.
