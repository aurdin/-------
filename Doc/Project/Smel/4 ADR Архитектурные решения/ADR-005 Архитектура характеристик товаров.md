# 1. Назначение

Документ фиксирует архитектурное решение по организации характеристик товаров проекта **Smart Electric (SmEl)**.

Решение определяет универсальную модель представления характеристик товаров и правила её использования.

# 2. Область применения

Решение распространяется на каталог товаров, информационную модель и связанные с ними функциональные компоненты SmEl.

В рамках решения характеристики товаров организуются по универсальной модели:

**«Характеристика → Значение характеристики» (Attribute → Attribute Value).**

# 3. Основная часть

В проекте **Smart Electric (SmEl)** характеристики товаров реализуются по универсальной модели **«Характеристика → Значение характеристики»**.

Характеристика описывает свойство товара, например:

- цвет;
    
- степень защиты;
    
- номинальный ток;
    
- напряжение;
    
- материал.
    

Значение характеристики содержит конкретное значение соответствующего свойства, например:

- Белый;
    
- IP44;
    
- 16 А;
    
- 230 В;
    
- Пластик.
    

Такая архитектура позволяет добавлять новые характеристики без изменения структуры базы данных.

## 3.1. Логическая модель

```
Товар
   │
   ├── Цвет ─────────────► Белый
   ├── Степень защиты ──► IP44
   ├── Напряжение ──────► 230 В
   ├── Материал ────────► Пластик
   └── Серия ───────────► Valena Life
```

## 3.2. Основные сущности

Архитектура включает следующие логические объекты:

- **Группа характеристик** — объединяет характеристики по смыслу, например «Электрические параметры», «Монтаж», «Конструкция».
    
- **Характеристика** — определяет тип свойства товара, например «Цвет», «Напряжение», «Степень защиты».
    
- **Значение характеристики** — определяет допустимое значение конкретной характеристики.
    
- **Товар** — связывается со значениями характеристик через отдельную таблицу связей.
    

# 4. Правила

В рамках данного архитектурного решения устанавливаются следующие правила:

1. Каждая характеристика создаётся один раз и используется повторно.
    
2. Значения характеристики принадлежат только своей характеристике.
    
3. Один товар может иметь любое количество характеристик.
    
4. Одна характеристика может использоваться у любого количества товаров.
    
5. Добавление новой характеристики не должно требовать изменения структуры базы данных.
    
6. Характеристики могут использоваться для фильтрации, поиска, сравнения товаров и формирования технических параметров.
    
7. Если характеристика имеет фиксированный набор значений, предпочтительно использовать соответствующий общий справочник из приложения `lists`.
    
8. Не допускается дублирование уже существующих общих справочников и значений при создании характеристик.
    

# 5. Использование справочников

Если характеристика имеет фиксированный набор значений, рекомендуется использовать соответствующий справочник из приложения `lists`.

Примеры:

- Цвет → `Color`;
    
- Степень защиты → `IP`;
    
- Серия → `Series`;
    
- Производитель → `Brand`;
    
- Страна → `Country`.
    

Использование общих справочников обеспечивает единообразие данных и исключает дублирование значений.

# 6. Причины выбора

Универсальная модель характеристик выбрана по следующим причинам:

- универсальность модели;
    
- отсутствие необходимости изменять структуру базы данных при появлении новых характеристик;
    
- возможность поддержки различных категорий товаров с разными наборами свойств;
    
- удобная реализация фильтрации и поиска;
    
- повторное использование характеристик и их значений;
    
- возможность использования общих справочников для фиксированных наборов значений.
    

# 7. Последствия

## 7.1. Преимущества

Решение обеспечивает:

- гибкую и расширяемую модель данных;
    
- минимизацию дублирования информации;
    
- простое добавление новых характеристик;
    
- единый механизм отображения технических параметров;
    
- возможность построения универсального фильтра каталога;
    
- поддержку сравнения товаров на основе характеристик;
    
- повторное использование общих справочных данных.
    

## 7.2. Ограничения

Решение требует:

- контроля уникальности характеристик и их значений;
    
- проверки существующих характеристик перед созданием новых;
    
- использования общих справочников из `lists` для характеристик с фиксированными значениями;
    
- контроля корректности связей между товарами, характеристиками и их значениями.

# 9. Заключительные положения

Универсальная модель **«Характеристика → Значение характеристики»** является базовым принципом организации характеристик товаров SmEl.

Решение фиксирует концептуальную модель характеристик и не определяет физическую реализацию в PostgreSQL и Django.

Конкретная структура таблиц, связей, ORM-моделей и API определяется последующими архитектурными решениями и реализацией проекта.
