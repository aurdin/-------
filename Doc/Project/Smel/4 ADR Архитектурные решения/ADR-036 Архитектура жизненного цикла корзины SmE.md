# 1. Назначение

ADR-036 определяет архитектуру жизненного цикла Cart и Cart Item в SmEl.

Документ устанавливает правила создания, хранения, изменения, актуализации и завершения жизненного цикла корзины с учётом различий между гостевым и авторизованным клиентом.

Цель решения — обеспечить предсказуемое поведение корзины между сеансами, контролируемое хранение временных данных и корректный переход от Cart к Checkout.

# 2. Область применения

Решение распространяется на:

- Cart;
    
- Cart Item;
    
- Guest Cart;
    
- авторизованного клиента;
    
- гостевого клиента;
    
- Session;
    
- Checkout;
    
- Product/SKU;
    
- Pricing;
    
- Stock;
    
- Order;
    
- Service Layer.
    

ADR-036 не определяет:

- механизм аутентификации;
    
- конкретную технологию хранения Session;
    
- конкретную структуру таблиц PostgreSQL;
    
- конкретную реализацию API;
    
- механизм резервирования товара;
    
- конкретную технологию фоновой очистки;
    
- конкретные UI-компоненты Frontend.
    

# 3. Основная часть

## 3.1. Cart как временный объект

Cart представляет текущее намерение клиента приобрести набор товарных позиций.

Cart не является заказом и не гарантирует:

- сохранение цены;
    
- наличие товара;
    
- сохранение скидки;
    
- сохранение акции;
    
- резервирование товара.
    

Актуальность содержимого корзины подтверждается Backend перед переходом к Order.

## 3.2. Типы корзины

SmEl поддерживает два основных типа корзины:

```
                 ┌── Guest Cart
Client ──────────┤
                 └── Customer Cart
```

### Guest Cart

Guest Cart принадлежит текущей гостевой Session.

Гостевая корзина:

- существует в рамках текущей сессии;
    
- не требует создания User;
    
- не сохраняется как постоянная корзина клиента после завершения сессии;
    
- содержит Cart Item только на время существования соответствующего контекста.
    

### Customer Cart

Корзина авторизованного клиента связана с User/Customer.

Customer Cart:

- сохраняется между сессиями;
    
- не зависит от завершения отдельной Session;
    
- может быть восстановлена при следующем входе клиента;
    
- управляется Backend.
    

## 3.3. Создание Cart

Корзина может быть создана:

- при первом добавлении товара;
    
- при явном обращении к корзине;
    
- другим предусмотренным бизнес-сценарием.
    

Конкретный момент физического создания Cart не является обязательным архитектурным требованием.

Для одного авторизованного клиента должна существовать одна активная основная корзина.

Для гостя активная корзина определяется текущей Session.

## 3.4. Добавление Cart Item

При добавлении товара Backend проверяет:

- существование SKU;
    
- возможность продажи;
    
- допустимость количества;
    
- доступность операции для клиента;
    
- актуальные коммерческие условия.
    

Добавление товара в Cart не создаёт Reservation согласно ADR-035.

Если соответствующий Cart Item уже существует, изменение количества выполняется согласно бизнес-правилам корзины.

Frontend не является источником истины для состава Cart.

## 3.5. Срок хранения Customer Cart

Для авторизованного клиента Cart не имеет короткого срока жизни, связанного с Session.

Cart может сохраняться между сессиями до наступления одного из условий завершения:

- клиент удалил корзину;
    
- корзина была очищена;
    
- применена политика хранения неактивных корзин;
    
- клиент или администратор инициировал удаление;
    
- выполнено другое предусмотренное бизнес-событие.
    

Таким образом, завершение Session само по себе не завершает Customer Cart.

## 3.6. Срок хранения Guest Cart

Guest Cart существует только в рамках текущей гостевой Session.

После завершения или истечения Session гостевая корзина считается утратившей актуальность.

Guest Cart не должна превращаться в постоянную клиентскую корзину автоматически.

Если гостевой клиент авторизуется, перенос содержимого Guest Cart в Customer Cart является отдельной бизнес-операцией и должен выполняться через Backend.

## 3.7. Срок хранения Cart Item

Cart Item наследует контекст жизненного цикла соответствующей Cart.

Для Guest Cart:

```
Guest Session
      │
      ▼
 Guest Cart
      │
      ▼
  Cart Item
      │
      ▼
Session ends
      │
      ▼
Cart Item expires
```

Для Customer Cart:

```
Customer Cart
      │
      ▼
  Cart Item
      │
      ▼
Persists between sessions
```

Однако длительное хранение Customer Cart не означает бессрочное хранение отдельных Cart Item.

Политика очистки неактивных Cart Item может применяться независимо от Session.

## 3.8. Актуальность Cart Item

Наличие Cart Item в корзине не означает, что товар всё ещё может быть приобретён на прежних условиях.

При обращении к корзине Backend может проверить актуальность данных.

Перед Checkout обязательна повторная проверка:

- существования SKU;
    
- доступности товара для продажи;
    
- количества;
    
- текущей стоимости;
    
- скидок;
    
- акций;
    
- валюты;
    
- коммерческих условий;
    
- доступного остатка.
    

Правила Pricing определяются ADR-034.

Правила Stock определяются ADR-011 и ADR-028.

## 3.9. Изменение товара после добавления в корзину

Изменения каталога, характеристик, цены, скидки, акции или остатков не должны автоматически создавать Order.

Cart содержит временное состояние намерения клиента.

Если коммерческие условия изменились, Backend при Checkout пересчитывает актуальные значения.

Если товар больше недоступен, Backend не должен создавать Order с недопустимой товарной позицией.

Cart Item может быть:

- удалён;
    
- помечен как недоступный;
    
- изменён;
    
- оставлен для последующего решения клиента.
    

Автоматическое удаление является отдельным бизнес-правилом и не является обязательным.

## 3.10. Очистка Cart

Cart может быть очищена:

- клиентом;
    
- после успешного оформления заказа;
    
- администратором в предусмотренном сценарии;
    
- политикой хранения;
    
- другим бизнес-событием.
    

После создания Order Cart не становится частью Order.

Order получает независимый набор Order Item.

Изменение Cart после создания Order не изменяет Order.

## 3.11. Переход Cart → Checkout

Основной переход:

```
Cart
 │
 ▼
Revalidation
 │
 ├── Product
 ├── Pricing
 ├── Stock
 └── Commercial Conditions
 │
 ▼
Checkout
 │
 ▼
Reservation
 │
 ▼
Order
```

Reservation создаётся согласно ADR-035.

Checkout не должен использовать устаревшее состояние Cart как окончательное основание для создания Order.

## 3.12. Завершение жизненного цикла Cart

Жизненный цикл Cart может быть представлен следующим образом:

```
Created
   │
   ▼
Active
   │
   ├──► Modified
   │
   ├──► Checkout
   │      │
   │      ▼
   │     Order
   │
   ├──► Cleared
   │
   └──► Expired / Archived
```

Конкретная физическая реализация состояний может отличаться.

Главным является различие между активной корзиной, корзиной, проходящей Checkout, и завершённым/неактивным состоянием.

## 3.13. Истечение срока хранения

Истечение срока хранения не должно автоматически создавать Order.

Для Guest Cart истечение Session означает завершение актуальности гостевой корзины.

Для Customer Cart истечение срока возможно только в рамках установленной политики хранения неактивных корзин.

При истечении срока:

- Cart перестаёт считаться активной;
    
- связанные Cart Item перестают считаться актуальными;
    
- Reservation не должен создаваться;
    
- активный Reservation, если он существует в отдельном процессе, обрабатывается по ADR-035;
    
- исторические данные могут сохраняться в зависимости от политики хранения.
    

## 3.14. Авторизация гостя

Если гость авторизуется, Backend должен определить правила объединения:

```
Guest Cart
     │
     ▼
Authentication
     │
     ▼
Customer Cart
```

Содержимое гостевой корзины может:

- объединяться с Customer Cart;
    
- заменять её содержимое;
    
- сохраняться отдельно;
    
- передаваться клиенту для подтверждения.
    

Конкретная стратегия объединения является отдельным бизнес-правилом и не фиксируется настоящим ADR.

## 3.15. Очистка неактивных корзин

Для Customer Cart допускается автоматическая очистка или архивирование длительно неактивных корзин.

Для Guest Cart очистка может выполняться после завершения Session или через техническую политику хранения.

Очистка должна выполняться контролируемо и не должна затрагивать:

- Order;
    
- Order Item;
    
- Payment;
    
- Delivery;
    
- исторические коммерческие данные заказа.
    

Очистка Cart не должна изменять уже созданный Order.

# 4. Правила

1. Cart и Order являются различными сущностями.
    
2. Cart является временным состоянием намерения клиента приобрести товар.
    
3. Guest Cart существует только в рамках текущей гостевой Session.
    
4. Customer Cart сохраняется между сессиями.
    
5. Завершение Session не завершает Customer Cart.
    
6. Cart Item наследует жизненный контекст соответствующей Cart.
    
7. Customer Cart не означает бессрочное хранение каждого Cart Item.
    
8. Добавление товара в Cart не создаёт Reservation.
    
9. Reservation создаётся на этапе Checkout согласно ADR-035.
    
10. Backend является источником истины для состава Cart.
    
11. Frontend не определяет окончательную актуальность Cart.
    
12. Перед Checkout выполняется повторная проверка содержимого Cart.
    
13. Цена, скидки и акции повторно проверяются согласно ADR-034.
    
14. Доступный остаток повторно проверяется согласно ADR-011 и ADR-028.
    
15. Изменение каталога или коммерческих условий не изменяет существующий Order.
    
16. Order Item создаётся независимо от Cart Item.
    
17. После создания Order изменения Cart не изменяют Order.
    
18. Истечение срока Cart не создаёт Order.
    
19. Истечение гостевой Session завершает актуальность Guest Cart.
    
20. Политика долгосрочного хранения Customer Cart может быть установлена отдельно.
    
21. Автоматическое удаление недоступных Cart Item не является обязательным.
    
22. Объединение Guest Cart и Customer Cart при авторизации является отдельным бизнес-правилом.
    
23. Очистка Cart не должна изменять Order, Payment или Delivery.
    
24. Все операции жизненного цикла Cart выполняются через Service Layer.

# 6. Заключительные положения

ADR-036 фиксирует различия между гостевой и авторизованной корзиной и определяет жизненный цикл Cart и Cart Item.

Основное архитектурное правило состоит в том, что **гостевая корзина живёт в рамках Session, а корзина авторизованного клиента сохраняется между сессиями**.

Cart не гарантирует цену, наличие или резервирование товара. Перед Checkout Backend выполняет повторную проверку актуальности и только после успешной проверки может инициировать резервирование согласно ADR-035.

Конкретные сроки хранения неактивных Customer Cart и Cart Item, а также стратегия объединения Guest Cart с Customer Cart при авторизации могут быть уточнены отдельными бизнес-правилами без изменения основной архитектуры.
