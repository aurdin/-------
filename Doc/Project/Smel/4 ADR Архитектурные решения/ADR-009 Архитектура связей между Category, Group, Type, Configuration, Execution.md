# 1. Назначение

Настоящее архитектурное решение логически продолжает ADR-007 и фиксирует принцип построения связей между основными уровнями классификации каталога SmEl.

Решение определяет строгую иерархию классификации и правила взаимосвязи между уровнями:

**Category → Group → Type → Configuration → Execution → SKU.**

# 2. Область применения

Решение применяется к классификационной структуре каталога **Smart Electric (SmEl)** и определяет логические связи между уровнями:

- `Category`;
    
- `Group`;
    
- `Type`;
    
- `Configuration`;
    
- `Execution`;
    
- `SKU`.
    

Вопросы хранения характеристик, брендов, серий, применяемости и альтернативных классификаций данным решением не определяются.

# 3. Основная часть

## 3.1. Иерархическая структура

Классификационная структура каталога строится как последовательная иерархия, в которой каждый уровень зависит только от непосредственно вышестоящего уровня.

```
Category
    │
    └── Group
            │
            └── Type
                    │
                    └── Configuration
                            │
                            └── Execution
                                    │
                                    └── SKU
```

Каждый объект классификации имеет ровно одного родителя и может иметь множество дочерних элементов.

Таким образом, связи между уровнями являются отношениями **один-ко-многим (1)**.

## 3.2. Логическая модель связей

```
Category (1)
      │
      └───────────────< Group (N)

Group (1)
      │
      └───────────────< Type (N)

Type (1)
      │
      └───────────────< Configuration (N)

Configuration (1)
      │
      └───────────────< Execution (N)

Execution (1)
      │
      └───────────────< SKU (N)
```

# 4. Правила

1. Каждый `Group` принадлежит только одной `Category`.
    
2. Каждый `Type` принадлежит только одной `Group`.
    
3. Каждая `Configuration` принадлежит только одному `Type`.
    
4. Каждое `Execution` принадлежит только одной `Configuration`.
    
5. Каждый `SKU` принадлежит только одному `Execution`.
    
6. Переход между уровнями осуществляется только по установленной иерархии.
    
7. Промежуточные уровни иерархии не пропускаются.
    
8. Дополнительные связи между уровнями не должны нарушать базовую иерархию и оформляются отдельными архитектурными решениями.
    

## 4.1. Независимость классификации от производителя

Уровни классификации не зависят от `Brand` и `Series`.

Одна и та же классификационная структура может использоваться одновременно для товаров различных производителей.

Пример:

```
Category
└── Электроустановочные изделия
    └── Розетки
        └── С заземлением
            └── Одинарная
                └── С крышкой
                    ├── Legrand Valena Life
                    ├── Legrand Etika
                    ├── BTicino Living Now
                    └── ...
```

Производитель и серия не являются частью базовой цепочки классификационных связей.

# 5. Обоснование

Выбор строгой иерархической модели обусловлен следующими причинами:

- строгая и понятная структура каталога;
    
- отсутствие дублирования классификационных элементов;
    
- независимость каталога от конкретных производителей;
    
- единая логика построения URL, навигации и хлебных крошек;
    
- простая реализация фильтрации на любом уровне иерархии;
    
- возможность масштабирования каталога без изменения базовой структуры.
    

# 6. Последствия

## 6.1. Преимущества

- единая система классификации для всех брендов;
    
- простота сопровождения каталога;
    
- удобная реализация REST API;
    
- высокая производительность при навигации по каталогу;
    
- возможность повторного использования классификационных уровней для разных производителей.
    

## 6.2. Ограничения

- элемент не может одновременно принадлежать нескольким родительским элементам;
    
- изменение положения элемента в иерархии влияет на все дочерние элементы и требует анализа последствий;
    
- дополнительные связи между уровнями не должны нарушать базовую иерархию;
    
- дополнительные способы классификации должны рассматриваться отдельными архитектурными решениями.
