# 1. Назначение

Настоящий документ определяет информационные требования проекта **SmEl (Smart Electric)**.

Документ устанавливает основные информационные объекты системы, их состав, взаимосвязи и требования к сохранению актуальности и исторической целостности данных.

# 2. Область применения

Информационные требования распространяются на данные, используемые в каталоге, ценообразовании, корзине, оформлении и сопровождении заказов, а также на данные клиентов, доставки, оплаты и административного управления.

Документ не определяет физическую структуру базы данных и технологию хранения данных.

# 3. Основные информационные объекты

SmEl должен поддерживать следующие основные информационные объекты:

- товар;
    
- категория;
    
- характеристика товара;
    
- изображение товара;
    
- цена;
    
- скидка;
    
- акция;
    
- наличие;
    
- клиент;
    
- корзина;
    
- позиция корзины;
    
- оформление заказа;
    
- заказ;
    
- позиция заказа;
    
- доставка;
    
- способ доставки;
    
- оплата;
    
- способ оплаты.
    

Состав объектов может расширяться в соответствии с требованиями проекта.

# 4. Товар

Информационный объект **Товар** должен содержать данные, необходимые для представления и идентификации товара.

Минимальный состав:

- уникальный идентификатор;
    
- артикул или иной код товара;
    
- наименование;
    
- описание;
    
- категория;
    
- характеристики;
    
- изображения;
    
- информация о доступности;
    
- сведения, необходимые для ценообразования.
    

Товар является исходным объектом каталога.

# 5. Категория

Информационный объект **Категория** должен обеспечивать классификацию товаров.

Категория должна иметь:

- уникальный идентификатор;
    
- наименование;
    
- признаки, необходимые для отображения и навигации;
    
- связь с товарами.
    

Должна поддерживаться возможность построения иерархии категорий, если она необходима для каталога SmEl.

# 6. Характеристики товара

Система должна обеспечивать хранение технических характеристик товаров.

Характеристика должна позволять определить:

- наименование характеристики;
    
- значение;
    
- единицу измерения, если она применима;
    
- связь с соответствующим товаром.
    

Набор характеристик может различаться для разных категорий товаров.

# 7. Изображения

Для товара система должна поддерживать хранение и использование изображений.

Изображение должно быть связано с соответствующим товаром и иметь данные, необходимые для его отображения.

# 8. Ценообразование

Информационная модель должна обеспечивать представление:

- базовой цены;
    
- действующей цены;
    
- скидки;
    
- акции;
    
- периода действия коммерческого условия;
    
- итоговой стоимости.
    

Система должна обеспечивать возможность определить, какое коммерческое условие применялось к товару в конкретный момент времени.

# 9. Наличие товара

Система должна хранить информацию, позволяющую определить доступность товара для продажи.

Информация о наличии должна быть отделена от основных данных товара.

Данные о наличии должны использоваться при проверке корзины и оформлении заказа.

# 10. Клиент

Информационный объект **Клиент** должен содержать данные, необходимые для идентификации пользователя и выполнения заказа.

Минимальный состав:

- идентификатор клиента;
    
- учётные данные;
    
- контактные данные;
    
- данные, необходимые для доставки;
    
- история заказов.
    

Состав персональных данных определяется отдельными требованиями безопасности и законодательства.

# 11. Корзина

Информационный объект **Корзина** должен содержать:

- идентификатор корзины;
    
- тип владельца или способ идентификации сессии;
    
- дату создания;
    
- дату последнего изменения;
    
- состояние корзины;
    
- позиции корзины.
    

Для авторизованного клиента корзина должна быть связана с клиентом и сохраняться между сеансами.

Для гостя корзина должна быть связана с текущей сессией.

# 12. Позиция корзины

**Позиция корзины** должна содержать:

- товар;
    
- количество;
    
- дату добавления;
    
- дату последнего изменения;
    
- данные, необходимые для контроля актуальности позиции.
    

Позиция корзины должна однозначно определять товар и его количество.

Цена каталога не должна считаться окончательно зафиксированной в момент добавления товара в корзину.

# 13. Актуальность корзины

Для каждой позиции корзины система должна иметь возможность определить её актуальность.

При проверке должны учитываться:

- существование товара;
    
- доступность товара;
    
- допустимое количество;
    
- текущая цена;
    
- действующие скидки;
    
- действующие акции;
    
- срок нахождения позиции в корзине;
    
- иные условия продажи.
    

Результат проверки должен позволять определить, может ли позиция участвовать в оформлении заказа.

# 14. Checkout

**Checkout** является информационным состоянием процесса оформления заказа.

Система должна иметь возможность временно хранить данные, необходимые для завершения оформления:

- состав актуальной корзины;
    
- данные клиента;
    
- способ доставки;
    
- данные получения;
    
- способ оплаты;
    
- рассчитанные коммерческие условия;
    
- итоговую стоимость.
    

Checkout не должен подменять собой созданный заказ.

# 15. Заказ

Информационный объект **Заказ** должен представлять исторически зафиксированный результат оформления покупки.

Заказ должен содержать:

- идентификатор;
    
- дату и время создания;
    
- клиента или данные покупателя;
    
- позиции заказа;
    
- стоимость товаров;
    
- применённые скидки и акции;
    
- стоимость доставки;
    
- итоговую стоимость;
    
- способ доставки;
    
- данные получения;
    
- способ оплаты;
    
- состояние заказа;
    
- состояние оплаты;
    
- состояние доставки.
    

# 16. Позиция заказа

**Позиция заказа** должна содержать историческую информацию о товаре на момент оформления заказа.

Минимальный состав:

- идентификатор товара;
    
- наименование товара;
    
- количество;
    
- цена;
    
- применённая скидка;
    
- итоговая стоимость позиции;
    
- данные, необходимые для идентификации товара.
    

Позиция заказа должна сохранять исторические значения независимо от последующих изменений карточки товара, цены, скидок или акций.

Основная информационная цепочка:

**Product → Cart Item → Checkout → Order Item**

# 17. Доставка

Система должна поддерживать информационные объекты:

- способ доставки;
    
- данные получения;
    
- стоимость доставки;
    
- состояние доставки.
    

Информация о выбранной доставке должна сохраняться в заказе.

# 18. Оплата

Система должна поддерживать информационные объекты:

- способ оплаты;
    
- идентификатор платёжной операции, если применимо;
    
- сумма оплаты;
    
- дата и время;
    
- состояние оплаты.
    

Информация о способе и состоянии оплаты должна быть связана с соответствующим заказом.

# 19. Историческая целостность

После создания заказа данные, определяющие его историческое содержание, должны сохраняться независимо от изменений исходных объектов.

Изменение:

- товара;
    
- цены;
    
- скидки;
    
- акции;
    
- наличия;
    
- данных каталога
    

не должно изменять исторические данные уже созданного заказа.

# 20. Актуальность данных

Система должна различать:

- текущие данные каталога;
    
- данные текущей корзины;
    
- данные процесса Checkout;
    
- исторические данные заказа.
    

Перед созданием заказа актуальные данные должны быть повторно проверены.

# 21. Локализация

Информационная модель должна поддерживать мультиязычное представление данных, если это предусмотрено требованиями SmEl.

Для локализуемых данных должны поддерживаться соответствующие языковые варианты.

Минимально учитываются:

- украинский;
    
- русский;
    
- английский.
    

# 22. Связи информационных объектов

Основные связи должны обеспечивать следующий информационный поток:

**Каталог → Товар → Позиция корзины → Checkout → Позиция заказа → Заказ**

При этом:

- товар является источником актуальных данных каталога;
    
- позиция корзины представляет выбранный товар;
    
- Checkout представляет процесс подготовки заказа;
    
- позиция заказа фиксирует исторические данные товара;
    
- заказ представляет завершённый результат оформления.
    

# 23. Требования к целостности

Система должна обеспечивать:

- уникальную идентификацию информационных объектов;
    
- непротиворечивость связанных данных;
    
- сохранение обязательных связей;
    
- невозможность создания заказа из неактуальной корзины;
    
- сохранение исторических данных заказа;
    
- корректное разделение текущих и исторических данных.

# 26. Заключительные положения

REQ-020 определяет информационные требования SmEl и устанавливает требования к основным информационным объектам системы.

Документ не определяет конкретную реализацию хранения данных.

На основании REQ-020 должна быть разработана **AMD-030 — Информационная модель SmEl**, в которой информационные объекты, их связи и правила будут представлены на архитектурном уровне.
