# 1. Назначение

Настоящий документ определяет бизнес-требования проекта **SmEl (Smart Electric)**.

Документ устанавливает цели интернет-магазина, основные направления его деятельности, категории пользователей и общие бизнес-сценарии, которые должны быть обеспечены системой.

# 2. Область применения

Бизнес-требования распространяются на интернет-магазин SmEl и определяют требования к организации электронной торговли электротехнической продукцией.

Требования являются основой для формирования функциональных, информационных и иных специализированных требований проекта.

# 3. Цели проекта

SmEl должен обеспечивать:

- представление ассортимента электротехнической продукции в электронном каталоге;
    
- предоставление пользователю информации о товарах;
    
- возможность выбора товаров;
    
- формирование и управление корзиной;
    
- оформление заказов;
    
- выбор способов доставки и оплаты;
    
- информирование клиента о состоянии заказа;
    
- управление ассортиментом, ценами и заказами;
    
- поддержку деятельности интернет-магазина средствами административной системы.
    

# 4. Основная бизнес-модель

SmEl представляет собой интернет-магазин, в котором клиент выбирает товары из каталога, формирует корзину и оформляет заказ.

Основной бизнес-процесс:

**Каталог → Выбор товара → Корзина → Проверка актуальности → Оформление заказа → Заказ → Доставка → Получение товара**

Система должна обеспечивать сохранение целостности данных и актуальности коммерческих условий на соответствующих этапах процесса.

# 5. Пользователи

Основными категориями пользователей являются:

- **гость** — пользователь, не прошедший аутентификацию;
    
- **авторизованный клиент** — зарегистрированный пользователь с учётной записью;
    
- **администратор** — пользователь, управляющий данными и операциями интернет-магазина.
    

В дальнейшем могут быть выделены дополнительные категории пользователей и операционные роли.

# 6. Требования к работе с каталогом

SmEl должен предоставлять клиенту возможность:

- просматривать каталог товаров;
    
- перемещаться по категориям;
    
- просматривать карточку товара;
    
- получать характеристики и описание товара;
    
- видеть актуальную цену;
    
- учитывать доступность товара;
    
- использовать поиск;
    
- использовать фильтрацию и сортировку.
    

Каталог должен обеспечивать структурированное представление ассортимента электротехнической продукции.

# 7. Требования к ценообразованию

SmEl должен обеспечивать формирование актуальной стоимости товара с учётом действующих коммерческих условий.

К блоку ценообразования относятся:

- базовая стоимость;
    
- скидки;
    
- акции;
    
- итоговая стоимость товара.
    

Стоимость, используемая при оформлении заказа, должна проверяться на актуальность.

# 8. Требования к корзине

SmEl должен обеспечивать добавление товаров в корзину, изменение количества и удаление товаров.

Для авторизованного клиента корзина должна сохраняться между сеансами.

Для гостя корзина должна существовать только в течение текущей сессии.

Перед переходом к оформлению заказа система должна проверить актуальность содержимого корзины, включая:

- существование товара;
    
- доступность товара;
    
- актуальность количества;
    
- актуальность цены;
    
- актуальность скидок и акций.
    

Срок нахождения товара в корзине и правила его актуализации должны быть определены специализированными требованиями.

# 9. Требования к оформлению заказа

SmEl должен обеспечивать преобразование актуальной корзины в заказ.

При оформлении заказа система должна:

- повторно проверить актуальность корзины;
    
- определить состав заказа;
    
- зафиксировать стоимость товаров;
    
- определить стоимость доставки;
    
- определить итоговую стоимость заказа;
    
- получить необходимые данные клиента;
    
- определить способ доставки;
    
- определить способ оплаты;
    
- создать заказ.
    

После создания заказа изменения в корзине не должны изменять уже сформированный состав заказа.

# 10. Требования к доставке

SmEl должен обеспечивать выбор способа доставки в соответствии с доступными вариантами.

Система должна учитывать:

- выбранный клиентом способ доставки;
    
- адрес или пункт получения;
    
- стоимость доставки;
    
- доступность способа доставки;
    
- ограничения, связанные с заказом.
    

Конкретный перечень способов доставки определяется специализированными требованиями.

# 11. Требования к оплате

SmEl должен обеспечивать выбор доступного способа оплаты при оформлении заказа.

Система должна сохранять информацию о выбранном способе оплаты и состоянии оплаты заказа.

Конкретные платёжные механизмы и интеграции определяются отдельными требованиями и архитектурными решениями.

# 12. Требования к заказу

После оформления заказа SmEl должен обеспечить его регистрацию и дальнейшее сопровождение.

Заказ должен содержать зафиксированные на момент оформления:

- состав товаров;
    
- количество;
    
- стоимость товаров;
    
- применённые скидки и акции;
    
- стоимость доставки;
    
- итоговую стоимость;
    
- данные клиента;
    
- способ доставки;
    
- способ оплаты.
    

Изменение исходных данных каталога, цены или корзины после создания заказа не должно изменять исторические данные уже оформленного заказа.

# 13. Требования к клиенту

Авторизованный клиент должен иметь возможность:

- управлять своей учётной записью;
    
- просматривать свои заказы;
    
- получать информацию о состоянии заказов;
    
- использовать сохранённую корзину между сеансами.
    

Гостю должна быть доступна покупка без обязательной регистрации, если это допускается установленными правилами оформления заказа.

# 14. Требования к административному управлению

Административная часть SmEl должна обеспечивать управление основными объектами интернет-магазина, включая:

- категории;
    
- товары;
    
- характеристики товаров;
    
- цены;
    
- скидки;
    
- акции;
    
- наличие;
    
- заказы;
    
- клиентов;
    
- способы доставки;
    
- способы оплаты.
    

Набор административных функций может быть расширен в соответствии с требованиями проекта.

# 15. Бизнес-правила

В SmEl должны соблюдаться следующие базовые правила:

1. Товар в каталоге и товар в заказе являются различными состояниями бизнес-данных.
    
2. Корзина является промежуточным состоянием перед оформлением заказа.
    
3. Содержимое корзины должно проходить проверку актуальности перед созданием заказа.
    
4. Цена в оформленном заказе фиксируется независимо от последующих изменений цены каталога.
    
5. Скидки и акции применяются в соответствии с условиями, действующими на момент оформления заказа.
    
6. Авторизованная корзина сохраняется между сеансами.
    
7. Гостевая корзина действует только в рамках текущей сессии.
    
8. Созданный заказ представляет собой самостоятельную историческую сущность.
    

# 16. Приоритет бизнес-требований

Приоритет требований определяется их влиянием на основной процесс электронной торговли:

**Каталог → Корзина → Checkout → Заказ**

Функции, непосредственно обеспечивающие этот процесс, относятся к основному функциональному контуру SmEl.

Дополнительные функции могут реализовываться после обеспечения основного контура.
