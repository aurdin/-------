# 1. Назначение

Настоящий документ определяет функциональные требования к интернет-магазину **SmEl (Smart Electric)**.

Документ детализирует функции системы, необходимые для реализации основных бизнес-процессов, определённых в REQ-001.

# 2. Область применения

Функциональные требования распространяются на пользовательские и административные функции SmEl, обеспечивающие работу каталога, ценообразования, корзины, оформления и сопровождения заказов.

# 3. Каталог

SmEl должен обеспечивать:

- отображение каталога товаров;
    
- отображение категорий;
    
- переход между категориями;
    
- поиск товаров;
    
- фильтрацию товаров;
    
- сортировку товаров;
    
- постраничное отображение результатов;
    
- просмотр карточки товара.
    

# 4. Карточка товара

Система должна обеспечивать отображение:

- наименования товара;
    
- изображения;
    
- описания;
    
- характеристик;
    
- текущей цены;
    
- информации о доступности;
    
- связанных коммерческих условий.
    

Карточка товара должна предоставлять возможность добавить товар в корзину.

# 5. Ценообразование

Система должна обеспечивать:

- получение текущей цены товара;
    
- применение действующих скидок;
    
- применение действующих акций;
    
- отображение итоговой стоимости;
    
- проверку актуальности коммерческих условий при оформлении заказа.
    

Стоимость должна определяться серверной частью системы.

# 6. Корзина

Система должна обеспечивать:

- добавление товара в корзину;
    
- изменение количества товара;
    
- удаление товара;
    
- просмотр содержимого корзины;
    
- отображение стоимости позиций;
    
- отображение общей стоимости корзины;
    
- проверку актуальности содержимого корзины;
    
- переход из корзины к оформлению заказа.
    

Для авторизованного клиента корзина должна сохраняться между сеансами.

Для гостя корзина должна существовать только в рамках текущей сессии.

# 7. Актуализация корзины

Перед оформлением заказа система должна проверить:

- существование каждого товара;
    
- доступность товара;
    
- допустимость количества;
    
- актуальность цены;
    
- актуальность скидок;
    
- актуальность акций;
    
- другие условия, влияющие на возможность оформления заказа.
    

При обнаружении изменений система должна уведомить клиента и предоставить возможность продолжить оформление с актуальными данными.

# 8. Время нахождения товара в корзине

Для товаров, находящихся в корзине, система должна обеспечивать контроль периода их нахождения в корзине.

Правила определения срока действия корзины и отдельных позиций должны быть установлены отдельным требованием.

Само нахождение товара в корзине не должно рассматриваться как подтверждение его резервирования, если резервирование отдельно не предусмотрено бизнес-правилами SmEl.

# 9. Оформление заказа

Система должна обеспечивать процесс:

**Корзина → Проверка актуальности → Checkout → Создание заказа.**

При оформлении заказа система должна:

- получить данные клиента;
    
- определить состав заказа;
    
- определить количество товаров;
    
- определить актуальные цены;
    
- определить применённые скидки и акции;
    
- определить способ доставки;
    
- определить стоимость доставки;
    
- определить способ оплаты;
    
- рассчитать итоговую стоимость;
    
- создать заказ.
    

# 10. Заказ

После создания заказа система должна обеспечить:

- уникальную идентификацию заказа;
    
- сохранение состава заказа;
    
- сохранение количества товаров;
    
- сохранение стоимости товаров;
    
- сохранение применённых скидок и акций;
    
- сохранение стоимости доставки;
    
- сохранение итоговой стоимости;
    
- сохранение данных клиента;
    
- сохранение способа доставки;
    
- сохранение способа оплаты;
    
- изменение состояния заказа;
    
- просмотр информации о заказе.
    

Данные оформленного заказа должны сохраняться независимо от последующих изменений каталога и корзины.

# 11. Клиент

Авторизованный клиент должен иметь возможность:

- входить в систему;
    
- управлять данными своей учётной записи;
    
- просматривать свои заказы;
    
- просматривать состояние заказа;
    
- использовать сохранённую корзину.
    

Гость должен иметь возможность просматривать каталог и формировать корзину в рамках текущей сессии.

Возможность оформления заказа гостем определяется отдельными требованиями.

# 12. Доставка

Система должна обеспечивать:

- отображение доступных способов доставки;
    
- выбор способа доставки;
    
- ввод или выбор необходимых данных получения;
    
- определение стоимости доставки;
    
- сохранение выбранного способа доставки в заказе.
    

# 13. Оплата

Система должна обеспечивать:

- отображение доступных способов оплаты;
    
- выбор способа оплаты;
    
- передачу необходимых данных для выполнения оплаты;
    
- фиксацию выбранного способа оплаты;
    
- получение и хранение состояния оплаты заказа.
    

Конкретные платёжные интеграции определяются требованиями REQ-040 и соответствующими ADR.

# 14. Уведомления

Система должна обеспечивать информирование клиента о значимых событиях, связанных с заказом.

Минимальный набор событий включает:

- создание заказа;
    
- изменение состояния заказа;
    
- изменение состояния оплаты;
    
- изменение состояния доставки.
    

Конкретные каналы уведомлений определяются интеграционными требованиями.

# 15. Административные функции

Административная часть должна обеспечивать управление:

- категориями;
    
- товарами;
    
- характеристиками;
    
- ценами;
    
- скидками;
    
- акциями;
    
- наличием;
    
- клиентами;
    
- заказами;
    
- доставкой;
    
- оплатой.
    

Администратор должен иметь возможность просматривать и изменять данные в пределах предоставленных ему полномочий.

# 16. Основной функциональный поток

Основной пользовательский сценарий должен поддерживать последовательность:

**Каталог → Выбор товара → Корзина → Проверка актуальности → Checkout → Заказ → Доставка → Получение товара.**

Дополнительные пользовательские сценарии не должны нарушать целостность основного процесса.

# 17. Связь с другими требованиями

REQ-010 является основанием для формирования:

- **REQ-020 — Информационные требования SmEl**;
    
- **REQ-030 — Нефункциональные требования SmEl**;
    
- **REQ-040 — Интеграционные требования SmEl**;
    
- **REQ-050 — Ограничения и бизнес-правила SmEl**.
    

REQ-010 также является одним из основных источников требований для **AMD-020 — Функциональная модель SmEl**.
