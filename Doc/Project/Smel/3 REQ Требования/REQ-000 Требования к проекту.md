# 1. Назначение

Настоящий документ определяет систему требований к проекту и устанавливает общие правила их формирования, классификации и использования при архитектурном проектировании и реализации интернет-магазина.

REQ-000 является корневым документом серии REQ и определяет структуру специализированных документов требований проекта.

# 2. Область применения

Требования распространяются на программную систему интернет-магазина SmEl, включая пользовательскую часть, серверную часть, данные, бизнес-логику, интеграции и административные функции.

Требования используются как исходная основа для разработки архитектурных моделей SmEl и последующих архитектурных решений.

# 3. Структура требований

Требования SmEl распределяются по следующим группам:

- бизнес-требования;
    
- функциональные требования;
    
- информационные требования;
    
- нефункциональные требования;
    
- интеграционные требования;
    
- ограничения и бизнес-правила.
    

Для каждой группы могут создаваться отдельные документы серии REQ.

# 4. Специализированные документы

Основными специализированными документами серии являются:

- **REQ-001 — Бизнес-требования SmEl (**SmEl Business Requirements)
    
- **REQ-010 — Функциональные требования SmEl (**SmEl Functional Requirements)
    
- **REQ-020 — Информационные требования SmEl (**SmEl Information Requirements)
    
- **REQ-030 — Нефункциональные требования SmEl (**SmEl Non-Functional Requirements)
    
- **REQ-040 — Интеграционные требования SmEl (**SmEl Integration Requirements**)**
    
- **REQ-050 — Ограничения и бизнес-правила SmEl (**SmEl Restrictions and Business Rules**)**
    

Состав серии может расширяться при появлении новых групп требований.

# 5. Связь с архитектурой

  

Требования серии REQ являются исходными данными для архитектурного проектирования SmEl.

Архитектурные модели серии AMD должны соответствовать принятым требованиям.

Архитектурные решения серии ADR должны учитывать требования и не должны противоречить им без соответствующего изменения требований или документированного архитектурного обоснования.

# 6. Принципы формирования требований

Требования SmEl должны быть:

- однозначными;
    
- проверяемыми;
    
- непротиворечивыми;
    
- необходимыми;
    
- трассируемыми;
    
- отделёнными от архитектурных решений;
    
- актуальными для текущего состояния проекта.
    

REQ фиксирует **что система должна обеспечивать**, а AMD и ADR определяют **как это организуется архитектурно**.

# 7. Жизненный цикл требований

Каждое требование проходит этапы:

**формирование → обсуждение → согласование → принятие → изменение или отмена.**

История изменения статуса документа сохраняется в его метаданных.

Изменение принятого требования должно быть отражено в соответствующем документе серии REQ и учтено в связанных архитектурных артефактах.

# 8. Связанные документы

- **STD-001 — Технологический стек SmEl**
    
- **AMD-001 — Контекст SmEl**
    
- **ADR-001–ADR-020 — Архитектурные решения SmEl**
    
- **AMD-020 и последующие архитектурные модели SmEl**
    

# 9. Заключительные положения

REQ-000 является корневым документом требований проекта SmEl.

Детальное содержание требований определяется специализированными документами серии REQ.

После формирования и принятия необходимых требований они используются как основание для разработки **AMD-020 — Функциональная модель SmEl** и последующих архитектурных моделей.
