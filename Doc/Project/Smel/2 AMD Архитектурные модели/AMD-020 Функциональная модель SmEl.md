# 1. Назначение

Настоящий документ определяет функциональную модель проекта **SmEl (Smart Electric)**.

Документ представляет основные функциональные блоки системы, их назначение, взаимосвязи и место в основных бизнес-процессах интернет-магазина.

AMD-020 разрабатывается на основании требований серии **REQ** и определяет функциональную структуру SmEl без детализации конкретной реализации программных компонентов.

# 2. Область применения

Функциональная модель охватывает основные функции пользовательской, серверной и административной частей SmEl.

Модель включает:

- каталог;
    
- поиск и навигацию;
    
- карточку товара;
    
- ценообразование;
    
- корзину;
    
- проверку актуальности;
    
- Checkout;
    
- заказ;
    
- оплату;
    
- доставку;
    
- управление клиентом;
    
- административное управление;
    
- интеграционное взаимодействие.
    

# 3. Основной функциональный контур

Основной функциональный контур SmEl:

**Каталог → Выбор товара → Корзина → Проверка актуальности → Checkout → Заказ → Оплата → Доставка → Получение товара**

Функциональные блоки должны обеспечивать прохождение данного процесса с сохранением целостности данных и соблюдением установленных бизнес-правил.

# 4. Функциональные блоки

Функциональная модель SmEl включает следующие основные блоки:

1. **Каталог**
    
2. **Поиск и навигация**
    
3. **Товар**
    
4. **Ценообразование**
    
5. **Корзина**
    
6. **Проверка актуальности**
    
7. **Checkout**
    
8. **Заказ**
    
9. **Оплата**
    
10. **Доставка**
    
11. **Клиент**
    
12. **Административное управление**
    
13. **Интеграции**
    

Каждый блок представляет самостоятельную функциональную область системы.

# 5. Каталог

Функциональный блок **Каталог** обеспечивает представление ассортимента товаров.

Основные функции:

- отображение категорий;
    
- отображение списка товаров;
    
- получение данных товара;
    
- переход между категориями;
    
- фильтрация;
    
- сортировка;
    
- отображение доступности;
    
- отображение актуальной стоимости.
    

Каталог предоставляет данные, необходимые для выбора товара клиентом.

# 6. Поиск и навигация

Функциональный блок **Поиск и навигация** обеспечивает нахождение товаров в каталоге.

Основные функции:

- поиск товара;
    
- навигация по категориям;
    
- применение фильтров;
    
- сортировка результатов;
    
- переход к карточке товара.
    

Поиск и навигация используют данные каталога и не изменяют исторические данные заказов.

# 7. Товар

Функциональный блок **Товар** обеспечивает представление выбранного товара.

Основные функции:

- отображение наименования;
    
- отображение описания;
    
- отображение характеристик;
    
- отображение изображений;
    
- отображение категории;
    
- отображение доступности;
    
- получение актуальной стоимости;
    
- добавление товара в корзину.
    

Товар является исходным объектом для формирования позиции корзины.

# 8. Ценообразование

Функциональный блок **Ценообразование** отвечает за определение стоимости товара и применение коммерческих условий.

В состав блока входят:

- базовая стоимость;
    
- действующая цена;
    
- скидки;
    
- акции;
    
- условия применения;
    
- период действия;
    
- итоговая стоимость.
    

Ценообразование должно обеспечивать получение актуального результата для корзины и Checkout.

Окончательная стоимость заказа фиксируется при создании заказа.

# 9. Корзина

Функциональный блок **Корзина** обеспечивает формирование набора выбранных товаров.

Основные функции:

- создание корзины;
    
- добавление товара;
    
- изменение количества;
    
- удаление товара;
    
- просмотр содержимого;
    
- сохранение корзины;
    
- определение состояния корзины;
    
- переход к проверке актуальности.
    

Для авторизованного клиента корзина сохраняется между сеансами.

Для гостя корзина действует в рамках текущей сессии.

# 10. Проверка актуальности

Функциональный блок **Проверка актуальности** предназначен для проверки возможности оформления содержимого корзины.

Проверяются:

- существование товара;
    
- доступность товара;
    
- количество;
    
- цена;
    
- скидки;
    
- акции;
    
- срок нахождения позиции в корзине;
    
- другие условия продажи.
    

Результатом является состояние каждой позиции и корзины в целом.

Переход к Checkout допускается только при выполнении необходимых условий.

# 11. Checkout

Функциональный блок **Checkout** обеспечивает подготовку заказа к созданию.

Основные функции:

- получение актуального состава корзины;
    
- повторная проверка данных;
    
- получение данных клиента;
    
- выбор способа доставки;
    
- ввод данных получения;
    
- выбор способа оплаты;
    
- расчёт стоимости;
    
- отображение итоговой стоимости;
    
- подтверждение оформления.
    

Checkout является промежуточным функциональным этапом между корзиной и заказом.

# 12. Заказ

Функциональный блок **Заказ** обеспечивает создание и сопровождение оформленного заказа.

Основные функции:

- создание заказа;
    
- фиксация состава заказа;
    
- фиксация стоимости;
    
- фиксация скидок и акций;
    
- фиксация стоимости доставки;
    
- фиксация данных покупателя;
    
- фиксация способа доставки;
    
- фиксация способа оплаты;
    
- управление состоянием заказа;
    
- просмотр заказа клиентом.
    

После создания заказа он становится самостоятельной исторической сущностью.

# 13. Оплата

Функциональный блок **Оплата** обеспечивает выполнение и сопровождение платёжных операций.

Основные функции:

- выбор способа оплаты;
    
- инициирование оплаты;
    
- получение результата;
    
- фиксация состояния оплаты;
    
- обработка ошибок;
    
- обработка повторных событий;
    
- связывание платежа с заказом.
    

Конкретный механизм взаимодействия с платёжными системами определяется архитектурой интеграций.

# 14. Доставка

Функциональный блок **Доставка** обеспечивает выбор и сопровождение доставки заказа.

Основные функции:

- выбор способа доставки;
    
- получение доступных вариантов;
    
- ввод или выбор данных получения;
    
- расчёт стоимости доставки;
    
- создание данных отправления;
    
- отслеживание состояния доставки;
    
- связывание доставки с заказом.
    

Конкретный состав функций зависит от используемых способов доставки и внешних систем.

# 15. Клиент

Функциональный блок **Клиент** обеспечивает работу с учётной записью и пользовательскими данными.

Основные функции:

- регистрация;
    
- аутентификация;
    
- управление учётной записью;
    
- управление контактными данными;
    
- использование сохранённой корзины;
    
- просмотр заказов;
    
- получение информации о состоянии заказов.
    

Гостевой пользователь может выполнять разрешённые операции без создания постоянной учётной записи.

# 16. Административное управление

Функциональный блок **Административное управление** обеспечивает управление интернет-магазином.

Основные функции:

- управление категориями;
    
- управление товарами;
    
- управление характеристиками;
    
- управление изображениями;
    
- управление ценами;
    
- управление скидками;
    
- управление акциями;
    
- управление наличием;
    
- управление клиентами;
    
- управление заказами;
    
- управление доставкой;
    
- управление оплатой.
    

Доступ к административным функциям предоставляется только уполномоченным пользователям.

# 17. Интеграции

Функциональный блок **Интеграции** обеспечивает взаимодействие SmEl с внешними системами.

Основные направления:

- платёжные системы;
    
- службы доставки;
    
- источники товарных данных;
    
- системы учёта наличия;
    
- сервисы уведомлений;
    
- иные внешние сервисы.
    

Интеграционный блок должен обеспечивать контроль обмена, обработку ошибок и сохранение целостности бизнес-операций.

# 18. Взаимодействие функциональных блоков

Основное взаимодействие функциональных блоков:

**Каталог → Товар → Корзина → Проверка актуальности → Checkout → Заказ**

Сопутствующие функции:

**Ценообразование → Каталог**

**Ценообразование → Корзина**

**Ценообразование → Checkout**

**Оплата ↔ Заказ**

**Доставка ↔ Заказ**

**Клиент ↔ Корзина**

**Клиент ↔ Заказ**

**Интеграции ↔ Оплата**

**Интеграции ↔ Доставка**

**Интеграции ↔ Каталог**

**Административное управление → функциональные данные SmEl**

# 19. Граница функциональной модели

Функциональная модель SmEl отделяет функции системы от внешних участников и сервисов.

Внутри SmEl находятся функции:

- управления каталогом;
    
- ценообразования;
    
- корзины;
    
- проверки актуальности;
    
- Checkout;
    
- управления заказом;
    
- управления клиентом;
    
- административного управления.
    

За пределами системы могут находиться:

- платёжные провайдеры;
    
- службы доставки;
    
- внешние источники данных;
    
- сервисы уведомлений;
    
- иные внешние системы.
    

# 20. Серверная ответственность

Критические функции должны выполняться или контролироваться серверной частью SmEl.

К ним относятся:

- расчёт стоимости;
    
- применение скидок и акций;
    
- проверка наличия;
    
- проверка актуальности корзины;
    
- создание заказа;
    
- изменение критических состояний заказа;
    
- контроль платёжных операций;
    
- контроль бизнес-правил.
    

Пользовательская часть не должна являться единственным источником результата критической бизнес-операции.

# 21. Жизненный цикл покупки

Функциональный жизненный цикл покупки:

**Выбор → Корзина → Проверка → Checkout → Создание заказа → Оплата → Доставка → Получение**

Каждый переход должен выполняться только при соблюдении условий соответствующего этапа.

Функциональная модель не предполагает автоматического перехода между состояниями при нарушении обязательных условий.

# 22. Основной функциональный поток

Основной поток выполняется следующим образом:

1. Клиент открывает каталог.
    
2. Клиент выбирает категорию или использует поиск.
    
3. Клиент открывает карточку товара.
    
4. Клиент добавляет товар в корзину.
    
5. Система сохраняет позицию корзины.
    
6. Клиент изменяет состав или количество товаров при необходимости.
    
7. Система выполняет проверку актуальности.
    
8. Клиент переходит к Checkout.
    
9. Система повторно проверяет необходимые данные.
    
10. Клиент выбирает доставку и оплату.
    
11. Система рассчитывает итоговую стоимость.
    
12. Клиент подтверждает оформление.
    
13. Система создаёт заказ.
    
14. Выполняется оплата в соответствии с выбранным способом.
    
15. Заказ передаётся в процесс доставки.
    
16. Клиент получает товар.
    

# 23. Альтернативные функциональные потоки

Функциональная модель должна учитывать альтернативные сценарии:

- товар отсутствует;
    
- изменилось количество доступного товара;
    
- изменилась цена;
    
- закончился срок действия скидки;
    
- закончился срок действия акции;
    
- позиция корзины стала неактуальной;
    
- платёж отклонён;
    
- платёжный сервис недоступен;
    
- служба доставки недоступна;
    
- данные клиента некорректны;
    
- заказ не может быть создан.
    

Каждый такой сценарий должен приводить к контролируемому результату без нарушения целостности данных.

# 24. Связь с информационной моделью

Функциональная модель работает с информационными объектами, определёнными в **REQ-020**.

Основная цепочка:

**Product → Cart Item → Checkout → Order Item → Order**

Функции системы должны обеспечивать корректное преобразование и передачу данных между соответствующими состояниями.

# 25. Связь с требованиями

AMD-020 разработан на основании:

- **REQ-000 — Требования к проекту SmEl**;
    
- **REQ-001 — Бизнес-требования SmEl**;
    
- **REQ-010 — Функциональные требования SmEl**;
    
- **REQ-020 — Информационные требования SmEl**;
    
- **REQ-030 — Нефункциональные требования SmEl**;
    
- **REQ-040 — Интеграционные требования SmEl**;
    
- **REQ-050 — Ограничения и бизнес-правила SmEl**.
    

# 26. Связь с архитектурными решениями

Функциональная модель должна учитывать принятые архитектурные решения:

- **ADR-001–ADR-020 — Архитектурные решения SmEl**.
    

При выявлении противоречий между функциональной моделью и принятыми ADR соответствующие архитектурные решения должны быть пересмотрены либо должно быть изменено соответствующее требование.

# 27. Основание для последующих моделей

AMD-020 является основанием для разработки последующих архитектурных моделей SmEl.

В частности:

- **AMD-030 — Информационная модель SmEl** должна детализировать информационные объекты и их связи;
    
- **AMD-040 — Компонентная модель SmEl** должна определить компоненты, реализующие функциональные блоки;
    
- **AMD-041 — Модель взаимодействий SmEl** должна детализировать взаимодействие компонентов;
    
- **AMD-050 — Технологическая модель SmEl** должна определить технологические средства реализации;
    
- последующие модели должны учитывать функциональную структуру AMD-020.
    

# 28. Заключительные положения

AMD-020 определяет функциональную структуру SmEl и основные взаимодействия функциональных блоков.

Модель фиксирует **что система функционально делает и как организован основной функциональный поток**, но не определяет конкретную программную реализацию.

На основании AMD-020 должна быть разработана последующая архитектурная детализация SmEl, начиная с **AMD-030 — Информационная модель SmEl**.
