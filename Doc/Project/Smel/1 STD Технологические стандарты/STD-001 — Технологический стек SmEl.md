## 1. Назначение
Настоящий документ фиксирует базовый технологический стек проекта **SmEl — Smart Electric** и определяет технологии, платформы и основные технологические ограничения, принимаемые в качестве исходной основы архитектуры проекта.
Документ является исходной технологической основой для последующего формирования архитектурных моделей, архитектурных решений и реализации проекта.
## 2. Область применения
Технологический стек применяется ко всем основным компонентам системы SmEl:
- frontend;
    
- backend;
    
- REST API;
    
- база данных;
    
- административная часть;
    
- инфраструктура разработки и локального запуска.
    

Конкретные архитектурные решения, не определяемые непосредственно технологическим стеком, оформляются отдельными ADR.

## 3. Основная часть

### 3.1. Frontend

В качестве основной технологии frontend принимается:

- **Vue 3** — framework пользовательского интерфейса;
    
- **TypeScript** — основной язык разработки;
    
- **Vite** — инструмент сборки и разработки;
    
- **Pinia** — управление состоянием;
    
- **Vue Router** — маршрутизация;
    
- **Tailwind CSS** — стилизация пользовательского интерфейса.
    

Frontend взаимодействует с backend исключительно через API.

### 3.2. Backend

В качестве основной технологии backend принимается:

- **Python** — язык разработки;
    
- **Django** — основной backend framework;
    
- **Django REST Framework (DRF)** — реализация REST API;
    
- **Django Admin** — административный интерфейс системы.
    

Backend является центральным компонентом бизнес-логики приложения.

### 3.3. API

Основным механизмом взаимодействия frontend и backend является **REST API**.

API обеспечивает:

- получение данных каталога;
    
- работу с товарами и категориями;
    
- работу с корзиной;
    
- оформление заказа;
    
- передачу данных между frontend и backend;
    
- интеграцию с внешними сервисами при необходимости.
    

Frontend не содержит самостоятельной реализации бизнес-логики, дублирующей backend.

### 3.4. База данных

В качестве основной СУБД принимается:

- **PostgreSQL**.
    

PostgreSQL является основной системой хранения данных SmEl.

Модель данных, ограничения целостности и правила доступа к данным определяются на уровне backend и базы данных.

### 3.5. Архитектурный принцип владения данными

Backend является **единым источником истины** для бизнес-данных и бизнес-правил системы.

Frontend не является источником истины для:

- цен;
    
- остатков;
    
- доступности товаров;
    
- расчёта стоимости;
    
- состояния заказа;
    
- иных бизнес-критичных данных.
    

Актуальное значение бизнес-данных определяется backend.

## 4. Правила

1. Основной frontend framework — **Vue 3**.
    
2. Основной язык frontend — **TypeScript**.
    
3. Основной backend framework — **Django**.
    
4. REST API реализуется посредством **Django REST Framework**.
    
5. Основная СУБД — **PostgreSQL**.
    
6. Frontend взаимодействует с backend через REST API.
    
7. Backend является единым источником бизнес-логики и актуальных бизнес-данных.
    
8. Новые технологические решения, существенно изменяющие настоящий стек, должны фиксироваться отдельным архитектурным решением ADR.
    
9. Использование дополнительных библиотек и инструментов допускается при условии их совместимости с настоящим стеком и архитектурой SmEl.

Изменения, затрагивающие фундаментальные технологические решения, должны сопровождаться соответствующим архитектурным решением.
